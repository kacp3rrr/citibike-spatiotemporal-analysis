Deploying the dashboard

Everything you need to put the dashboard online and keep it there. Skip this file entirely if you just want to run it locally — that’s covered in the main README.

The idea in one line

dashboard-deploy is master plus four generated files.

Those four files (the trained model, its metrics, the station list, and the borough summary) are too “generated” to belong on master, but Streamlit needs them to run. So they live on their own branch, and that’s the branch Streamlit builds.

master dashboard-deploy
Notebooks, figures, dashboard code yes yes
The 4 generated files no yes
What people see on GitHub yes —
What Streamlit runs — yes

The one rule: changes flow master → dashboard-deploy, never backwards. Merging the other way would drag the generated files onto master.

First-time deploy

Do these once, in order.

1. Push the project to GitHub

Streamlit can only see code that’s on GitHub, so this has to happen first.

git add .
git commit -m "Add Streamlit dashboard"
git push origin master

The four generated files are gitignored, so this commit contains code only — you don’t have to be careful about it.

2. Build the model files

Needs data/processed/, which comes from running notebooks/01_setup.ipynb. You do not need to run notebooks 02–04 for this.

pip install -r dashboard/requirements.txt
python dashboard/export_artifacts.py

This trains the Random Forest and writes:

  • dashboard/model_artifacts/rf_model.pkl (~4 MB)
  • dashboard/model_artifacts/model_metadata.json
  • dashboard/data/station_lookup.csv
  • dashboard/data/borough_stats.csv

3. Create the deploy branch

git checkout -b dashboard-deploy

git add -f dashboard/model_artifacts/ dashboard/data/
git commit -m "Add dashboard artifacts"
git push -u origin dashboard-deploy

git checkout master

Why -f? Those files are gitignored on purpose, so you can’t add them by accident. The -f (force) is you saying “yes, I mean it, just here.” You only need it this once — after this commit git tracks them on this branch permanently.

4. Turn it on

Go to share.streamlit.io → New app, and set:

Field Value
Repository kacp3rrr/citibike-spatiotemporal-analysis
Branch dashboard-deploy
Main file path dashboard/app.py
Python version 3.12 or 3.13

Not Python 3.14 — Streamlit doesn’t offer it, and dashboard/requirements.txt is written for 3.12/3.13 on purpose.

5. Add your link to the README

Once it’s live you’ll get a URL like https://citibike-spatiotemporal-analysis.streamlit.app. Put it at the top of README.md, replacing the placeholder link on line 7.

Changing things later

Changed something in dashboard/ (the common case)

Edit on master as normal, then push the change through:

# on master: edit, commit, push as usual
git push origin master

git checkout dashboard-deploy
git merge master
git push
git checkout master

Streamlit redeploys automatically. Nothing else to do.

You can edit dashboard-deploy directly and skip the merge — the live app will update fine. The catch is that master’s copy of the dashboard code then falls behind what’s actually running, so what people read on GitHub stops matching the live site. If you do it anyway and want the change on master later, git cherry-pick <commit> brings the code across without the generated files.

Re-ran the notebooks and want the app to match

python dashboard/export_artifacts.py

git checkout dashboard-deploy
git merge master
git add -f dashboard/model_artifacts/ dashboard/data/
git commit -m "Refresh dashboard artifacts"
git push
git checkout master

If you do this, the numbers shown in the dashboard are hardcoded in dashboard/utils.py (KEY_STATS) — check they still match your new notebook output.

Just changed notebooks or the README

Nothing to do. The live app only re-deploys if you push to dashboard-deploy, and none of that affects it.

If something goes wrong

App won’t start / “file does not exist” Check the branch is dashboard-deploy and not master — master doesn’t have the model files. Streamlit’s settings let you switch branches without redeploying from scratch.

“No module named …” Streamlit installs dashboard/requirements.txt (it checks the entrypoint’s folder before the repo root). If you added an import, add the package there — not to the root requirements.txt, which is for the notebooks.

Model fails to load / version warning scikit-learn is pinned in dashboard/requirements.txt because a saved model has to be opened by the same version that wrote it. If you upgrade scikit-learn locally, change that pin and re-run export_artifacts.py.

Dashboard shows warnings instead of the predictor or map That’s it telling you the generated files are missing — you’re either on the wrong branch, or step 2 hasn’t been run.

App is slow the first time someone opens it Streamlit puts apps to sleep after about a week of no visitors. It wakes on the next visit and takes a few seconds. Worth knowing before someone opens your link cold in an interview.

Accidentally merged dashboard-deploy into master The generated files are now tracked on master. Undo with:

git rm --cached -r dashboard/model_artifacts/ dashboard/data/
git commit -m "Remove generated files from master"

They stay on your disk and on dashboard-deploy — this only untracks them here.

## If something goes wrong

**App won't start / "file does not exist"**
Check the branch is `dashboard-deploy` and not `master` — `master` doesn't have the
model files. Streamlit's settings let you switch branches without redeploying from
scratch.

**"No module named ..."**
Streamlit installs `dashboard/requirements.txt` (it checks the entrypoint's folder
before the repo root). If you added an import, add the package there — not to the
root `requirements.txt`, which is for the notebooks.

**Model fails to load / version warning**
`scikit-learn` is pinned in `dashboard/requirements.txt` because a saved model has
to be opened by the same version that wrote it. If you upgrade scikit-learn locally,
change that pin *and* re-run `export_artifacts.py`.

**Dashboard shows warnings instead of the predictor or map**
That's it telling you the generated files are missing — you're either on the wrong
branch, or step 2 hasn't been run.

**App is slow the first time someone opens it**
Streamlit puts apps to sleep after about a week of no visitors. It wakes on the next
visit and takes a few seconds. Worth knowing before someone opens your link cold in
an interview.

**Accidentally merged `dashboard-deploy` into `master`**
The generated files are now tracked on `master`. Undo with:

```bash
git rm --cached -r dashboard/model_artifacts/ dashboard/data/
git commit -m "Remove generated files from master"
```

They stay on your disk and on `dashboard-deploy` — this only untracks them here.
